# GitHub 仓库目录浏览器：功能测试报告

本报告覆盖三类验证场景：
1. 公开热门仓库的目录拉取
2. 个人私有仓库的授权拉取
3. 10 级以上嵌套目录的复杂项目结构渲染

---

## 1. 测试环境

- 系统：macOS
- 浏览器：任一现代浏览器（Chrome / Safari / Firefox）
- 服务端启动命令：

```bash
python -m github_browser.backend --host 127.0.0.1 --port 8000
```

---

## 2. 场景一：公开热门仓库目录拉取

### 2.1 用例信息

- 目标：验证无 token 情况下可正常解析链接、加载根目录、按需展开子目录、点击文件展示内容
- 示例仓库（可替换）：
  - `https://github.com/psf/requests`
  - `https://github.com/pallets/flask`

### 2.2 步骤

1. 在页面“GitHub 链接”输入示例仓库链接
2. 点击“加载目录”
3. 展开 `requests/`、`src/`、`docs/` 等任意目录（示例视仓库结构而定）
4. 点击任意 `.py` / `.md` 文件

### 2.3 预期结果

- 页面能显示 `owner/repo@branch` 信息
- 目录可展开/折叠
- 点击文本/代码文件，右侧展示内容并可高亮
- “速率限制”展示 `remaining/limit` 并随请求减少

## 3. 场景二：私有仓库授权拉取（PAT）

### 3.1 用例信息

- 目标：验证 PAT 校验、私有仓库目录与文件内容可访问
- 前置条件：测试者拥有至少一个私有仓库，且创建了具有读取权限的 PAT

### 3.2 步骤

1. 生成 PAT：
   - Classic PAT：包含 `repo` scope
   - Fine-grained PAT：对目标私有仓库授予读取权限（例如 Contents: Read）
2. 将 PAT 粘贴到页面“GitHub Token（PAT）”
3. 点击“保存到会话”
4. 输入私有仓库链接（例如 `https://github.com/<you>/<private_repo>`）
5. 点击“加载目录”，并展开目录、点击文件

### 3.3 预期结果

- 点击“保存到会话”后，令牌校验成功（无 401）
- 私有仓库目录正常显示，展开目录无 404/403
- 点击文件可展示内容/下载
- 点击“取消授权”后，重新加载私有仓库应出现“权限不足/仓库不存在”等可理解提示

## 4. 场景三：10 级以上嵌套目录的结构渲染

### 4.1 用例信息

- 目标：验证深层目录展开/渲染正常，且不会一次性拉取导致页面卡死
- 仓库选择建议：
  - 使用你自己的测试仓库构造 10+ 层目录（最稳定）
  - 或选择具备较深嵌套的公开仓库（可替换）

### 4.2 步骤

1. 输入目标仓库链接并“加载目录”
2. 逐层展开，直到达到 10 层以上嵌套
3. 在最深层点击文件节点查看内容
4. （可选）点击“加载完整目录”验证全量遍历流程

### 4.3 预期结果

- 每次展开只触发对应目录的一次请求（懒加载生效）
- DOM 渲染流畅，无明显卡顿
- 深层文件可正常展示/下载
- 在接近速率上限时出现预警提示，不会静默失败

---

## 5. 错误处理覆盖检查

在以下情况下页面需给出用户可理解提示：
- 无效链接：提示格式错误/缺少 owner/repo/分支名
- 仓库不存在：提示 GitHub API 404 信息
- 权限不足/私有仓库未授权：提示 404/403 及原因（含可能的 scopes 不足）
- token 失效：提示 401
- 速率限制耗尽：提示 remaining=0 与 reset 时间
- 文件过大：提示无法直接展示，并提供“在 GitHub 打开”/“下载”入口
